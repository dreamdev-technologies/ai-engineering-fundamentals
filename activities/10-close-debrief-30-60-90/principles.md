# The four principles

Put this on screen for the debrief.

## 1. Set up for flow

Work moves through the organisation and the architecture in small steps, without long waits and hand-offs. Most of a feature's lead time is spent waiting, not being worked on; the value stream map shows where.

## 2. Build quality in

The person doing the work is responsible for it being right. Quality is not inspected in by someone else later, and a later inspection does not make a delegated change safe.

## 3. Automate validation

Every change is checked by something that runs without anyone remembering to run it: tests, performance budgets, security scans. Anything a person has to remember will be forgotten. Anything an agent has to be asked to run will be skipped.

## 4. Keep batches small

Small changes, checked often. The smaller the change, the smaller the damage when it is wrong and the quicker the check tells you.

## The equation under all four

**Delegation you can extend = verification you have built.**

You can hand an agent as much work as you can check. Context tells it what good looks like here; validation proves it did the job. Without validation you are the check, for every change, forever.
